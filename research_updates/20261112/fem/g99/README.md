# G99 全波对照的模型输入

G99 比较相同深度、开口、底部和周期的直壁 A3 与每侧 8 段平面近似的 A0。H≈98.097 μm、底宽≈34.655 μm、开口≈71.740 μm、周期 80 μm，底部 SiO₂ 为 3 μm。波长为 10.5 μm，法向 s 偏振。钛使用公开的光学常数作为阻抗边界，底填充使用公开 SiO₂ 光学常数。此处提供模型输入；保存结果按新主机独立审查。

- `CavityFloorFilm.java` 和 `FlatObliqueAdmission.java` 包含几何、薄膜、周期端口、源控制及独立功率核算。
- `plan.json`、`material.json`、`launch_manifest.json` 记录两个案例、材料及验证条件。`FROZEN_SOURCE_NOTE.json` 保留原冻结哈希，供私有原件校验。
- 在新服务器独立任务目录准备新任务时，将 `__STAGE_ROOT__` 配置为新服务器独立项目目录，`__COMSOL_BIN__` 配置为已验证的 COMSOL Windows 批处理和编译器目录。Java 的 `__STAGE_ROOT_PREFIX_JAVA__` 需要设置为允许的项目数据父目录，保留结尾的目录分隔符并按 Java 字符串规则转义。JSON 路径按 JSON 规则转义。历史结果继续保留在旧服务器；新 G99 求解由这些模型输入重建，不依赖旧 `.mph`、WSL 镜像或 OOC 缓存。
- 迁移目录发生变化时，应重新生成包含相关文件哈希的新清单及队列收据，检查安装和实际编译，依次做平面源校准、两个实际网格和物理解算。`launch_manifest.json` 内仍保留原冻结来源哈希，不能把它直接作为新主机启动清单使用；其中的 `build_release.py` 来源记录对应本地构建器，本公开模板未包含该文件。部署时应另备可移植构建器，生成只绑定新任务实际文件的新清单。`window.json` 由父队列首次运行自动生成，不应复制旧任务的窗口、锁或状态文件。原哈希用于验证旧版，不应用于改过路径的新副本。根据新主机实际内存、磁盘和计算许可确认容量再提交。

公开模板的完整性可由上一级发布清单复核。该目录不含服务器端保存的 `.mph`、日志、排程身份或直接访问凭证。

当前控制器依赖 Windows PowerShell、任务进程查询与 D 盘健康/空间指标。新主机若不是同一平台或盘符，先适配这层执行配置，再提交新任务。物理几何、材料及功率计算保持可追溯；不能为了迁移修改既有结果或质量标签。
